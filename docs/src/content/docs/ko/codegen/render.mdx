> Handlebars 템플릿 렌더링 래퍼.

## 설계 원칙: 얇은 템플릿

템플릿은 **파일 골격만 담당**합니다(헤더 주석, import, 네임스페이스 열고 닫기). 토큰별 리터럴 포맷팅은 **모두 target의 TS에서 완료**하여, 조립된 `body` 문자열을 템플릿에 먹입니다.

```
target.ts:  토큰별 포맷팅 → body 문자열로 조립
                        ▼
render.ts:  render('android/LhTokens.kt.hbs', { package, imports, body })
                        ▼
템플릿:     헤더 주석 + package 선언 + imports + {{{body}}}
```

이점: 템플릿 안에 복잡한 handlebars 로직이 없고, 리터럴 포맷을 바꾸려면 target의 TS만, 파일 골격을 바꾸려면 템플릿만 수정하면 되어 서로 간섭하지 않습니다.

## 함수

### `loadTemplate(name: string): HandlebarsTemplateDelegate`

내부 함수입니다. 템플릿명으로 `codegen/templates/<name>`을 읽습니다:

```ts
const compiled = Handlebars.compile(source, { noEscape: true })
cache.set(name, compiled)   // 컴파일 결과를 캐싱하여 반복 컴파일 방지
```

<Aside type="tip" title="왜 반드시 `noEscape: true`여야 하는가">
템플릿 내용에는 `<` `>` `#` 등의 문자가 포함됩니다(C 헤더 가드 `#ifndef`, `#define`, Kotlin 제네릭). 기본 HTML 이스케이프가 이들을 파괴하므로 반드시 꺼야 합니다.
</Aside>

템플릿 디렉터리는 상수 `TEMPLATES_DIR`로 지정됩니다(`codegen/templates`).

### `render<T>(templateName: string, data: T): string`

유일한 외부 인터페이스입니다:

```ts
return loadTemplate(templateName)(data)
```

각 target에 필요한 호출은 이 한 줄뿐입니다.

## 커스텀 helper는 없습니다

템플릿은 **handlebars helper를 하나도 등록하지 않고**, 내장 기능만 사용합니다:

| 문법 | 용도 |
| --- | --- |
| `{{{ }}}` | 삼중 중괄호 + `noEscape`, 미리 포맷팅된 `body` 삽입 |
| `{{#each}}` | import 목록 등의 배열 순회 |
