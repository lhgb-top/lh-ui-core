> lh-ui-core는 lh-ui 가족 **네이티브 혈통**의 빌드 시간 중심입니다.

## 이 리포지터리는 무엇인가

`@lh-ui/core`는 디자인 토큰의 **유일한 원본**, 컴포넌트 계약과 골든 케이스의 소재지이며, 중성 토큰에서 4개 네이티브 플랫폼의 언어 골격을 생성하는 codegen 도구를 겸합니다.

이것은 **런타임 의존성이 아닙니다**. 빌드 시에만 동작합니다: 플랫폼 독립적인 JSON 토큰과 컴포넌트 계약을 Android(Kotlin) / iOS(Swift) / HarmonyOS(ArkTS) / C 네 개 네이티브 플랫폼으로 생성하고, 각 플랫폼의 UI 라이브러리가 구현을 직접 작성합니다. **네이티브 플랫폼의 런타임에는 JavaScript가 없습니다.**

## 두 혈통 아키텍처

가족에는 서로 독립적이고 연결되지 않는 두 혈통이 있습니다:

```
lh-ui 가족
├── Web 혈통: lh-ui-share(TS core + SCSS 유일 스타일 소스) → plus / vue2 / react / uniapp
└── 네이티브 혈통: 이 리포지터리(JSON 토큰 + 사양 + codegen) → android / ios / harmony / windows
```

이 리포지터리와 `lh-ui-share` 사이에는 **코드 의존성이 전혀 없으며**, 각각 독립적으로 폐쇄되고 별도로 릴리스됩니다. 브랜드와 시각적 통일은 가족 문서 리포지터리의 `docs/설계 언어 기준선.md`가 제공하는 수동 정렬 메커니즘에 의존하며, 자동 동기화는 하지 않습니다.

## 3계층 계약

이 리포지터리의 내용은 서로 독립적이면서도 서로를 참조하는 3계층의 JSON 계약으로 구성됩니다:

| 계층 | 위치 | 답하는 질문 |
| --- | --- | --- |
| **토큰** | `tokens/*.json` | "인터페이스가 어떻게 보이는가" — 색상값, 간격, 글자 크기, 모서리 둥글기, 그림자, 모션, z-index, 컴포넌트 수준 치수 |
| **계약** | `specs/*.json` | "컴포넌트가 어떤 능력을 가지는가" — props / 열거형 / 기본값 / 이벤트 / 슬롯 / 동작 |
| **케이스** | `cases/*.json` | "컴포넌트를 어떻게 테스트하는가" — 크로스 플랫폼으로 번역 가능한 given/when/then 동작 수준 어서션 |

codegen은 **토큰**만 소비하여 4개 플랫폼의 골격을 생성합니다. **계약**과 **케이스**는 현재 각 네이티브 플랫폼에서 사람이 소비합니다(향후 타입 골격과 테스트 템플릿의 자동 생성으로 확장될 수 있습니다).

## 토큰 시드

이 리포지터리 `tokens/*.json`의 초기값은 `lh-ui-share/styles/theme/common/variables.scss`와 `var-dark.scss`에서 일회성으로 추출한 정렬 시드입니다(2026-10-10, 가족 `docs/설계 언어 기준선.md` 참고). 이후 두 리포지터리는 각자 진화하며 **더 이상 동기화하지 않습니다**. 브랜드 수준 토큰(색판, 간격 스케일)의 변경은 반드시 이 기준선 문서에 등록해야 합니다.

## 이 문서를 읽어야 할 사람

- **네이티브 플랫폼 개발자**(android / ios / harmony / windows): `dist/` 산출물의 명명 규칙, 단위 환산, 다크 메커니즘을 이해하고, 토큰이 어디서 오는지, 값이 어떻게 계산되는지 알 수 있습니다.
- **이 리포지터리의 유지 보수자**: codegen 파이프라인의 각 모듈 역할과 함수를 이해하고, 템플릿을 수정하거나 토큰과 컴포넌트를 추가할 수 있습니다.
