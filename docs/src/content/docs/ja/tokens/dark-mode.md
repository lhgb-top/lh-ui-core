## インクリメンタルオーバーライド

ダークファイル（`"$dark": true`）は**ライトと異なるキーだけを宣言**し、オーバーライドしないキーはライトの値を引き継ぎます：

```json
// color-dark.json
{
  "$namespace": "color",
  "$dark": true,
  "$description": "ライトと異なるキーのみを宣言し、未オーバーライドのキーは color.json を引き継ぐ",
  "primary": { "default": { "value": "#3D649E" } }
}
```

`color.primary.hover`、`.active` など列挙されていないキーは、ダークでもライトの値を引き継ぎます。削減の原則は**キー単位の比較**です：ライトの値と完全に同じキーは一律で削除されます（例えば `onPrimary` は両テーマとも `#FFFFFF`、`disabled.*` は両テーマとも同じ ref の組なので、いずれもダークファイルには現れません）。

## 名前空間は必ず揃える

ダークファイルはライトファイルと**同じ `$namespace`** を宣言しなければなりません（`color-dark.json` は `"$namespace": "color"` を明示）。そうして初めてオーバーライドキーが同じパスに落ちます。

## ダーク ref のローカル解決

ダークファイル内の `ref` は `resolveDarkRef` で解決し、ルールはライトと異なります：

1. 対象が**ダーク名前空間内**にあり、かつ ref → ダーク内でチェーンを再帰的にたどる（ダークがダークを参照して初めて同一テーマの値になる）
2. 対象がダーク名前空間内にあり、かつリテラル値 → ダーク値を返す
3. 対象がダーク名前空間内に**ない** → **ライト名前空間へフォールバック**して値を取る

```json
// ダークがダークを参照：ダークの primary.active を取る
"selectedDark": { "ref": "color.primary.active" }
```

ダーク ref にも循環検出があり（`检测到暗色令牌引用环`）、対象はライトセット / ダークセットのいずれかに存在しなければならず、そうでなければ `暗色令牌 X 引用不存在` を投げます。

## color-mix の事前計算

web 血脈のダークは `color-mix()` を多用しますが、**ネイティブ端にはこのランタイム能力がありません**。そのためビルド期に**リテラルの色値へ事前計算**し、計算の根拠を description に書きます：

```json
"selected": {
  "value": "#B1C1D8",
  "description": "color-mix(primary 40%, #fff) から事前計算。ダークパネルのコントラスト比 5.2:1"
},
"primary": {
  "bg": {
    "value": "rgba(61, 100, 158, 0.25)",
    "description": "color-mix(primary 25%, transparent) から事前計算"
  }
}
```

## 生成物の形態

`resolveTokens` は `TokenSet.dark` を生成します：フラットな `Map<path, TokenValue>` で、オーバーライドされたキーのみを含みます。各端の target がそれぞれの出し方を決めます：

| プラットフォーム | ダークの仕組み |
| --- | --- |
| Android | 独立した `object LhDarkTokens` |
| iOS | 独立した `public enum LhDarkTokens` |
| HarmonyOS | 独立した `export class LhDarkTokens` |
| **C** | **同名マクロの再定義**——ダークのヘッダーファイルをライトの後で include し、同名の `#define` をそのまま上書きする |

## 孤児ダークパス

2 種類の異常が `orphanDarkPaths` に記録されます（**codegen は中断しません**。`pnpm verify:tokens` が報告します）：

- ダークキーに**型がない**（自身の type もなく、ライトセットに同名キーもなく継承できない）→ そのキーをスキップし、オーバーライド表に書き込まない
- ダークキーがライトセットに**存在しない**（孤児）→ オーバーライド表には書き込むが、報告する

## ダークのオーバーライド範囲

現在ダークがオーバーライドするのは `color.*` 名前空間のみです（正確なキー数はバージョンによって変わります。[トークンリファレンス](./reference) ページのダーク列を参照）。色以外の名前空間（間隔、角丸、フォントサイズなど）はダークでもライトの値を引き継ぎます——`dist/docs/tokens.md` で色以外の行のダーク列が `—` なのはこのためです。

[トークンリファレンス](./reference) ページでは、各トークンのライト値とダーク値を同時に確認できます。
