> The Handlebars template rendering wrapper.

## Design principle: thin templates

The templates **only carry the file skeleton** (header comment, imports, namespace open/close). Per-token literal formatting **is entirely done in the target's TypeScript**, which feeds the assembled `body` string to the template.

```
target.ts:  format token by token → assembled into a body string
                        ▼
render.ts:  render('android/LhTokens.kt.hbs', { package, imports, body })
                        ▼
template:   header comment + package declaration + imports + {{{body}}}
```

The benefit: no complicated handlebars logic inside the templates — changing a literal format only touches the target's TS, and changing the file skeleton only touches the template, without interfering with each other.

## Functions

### `loadTemplate(name: string): HandlebarsTemplateDelegate`

An internal function. Reads `codegen/templates/<name>` by template name:

```ts
const compiled = Handlebars.compile(source, { noEscape: true })
cache.set(name, compiled)   // The compiled result is cached to avoid recompilation
```

<Aside type="tip" title="Why `noEscape: true` is mandatory">
The template content contains characters like `<`, `>`, `#` (the C header guards `#ifndef`, `#define`, Kotlin generics). The default HTML escaping would corrupt them, so it must be turned off.
</Aside>

The template directory is given by the `TEMPLATES_DIR` constant (`codegen/templates`).

### `render<T>(templateName: string, data: T): string`

The only public interface:

```ts
return loadTemplate(templateName)(data)
```

Every target needs only this one call.

## No custom helpers

The templates **register no handlebars helpers at all**; only built-in capabilities are used:

| Syntax | Purpose |
| --- | --- |
| `{{{ }}}` | Triple braces plus `noEscape`, for inserting the pre-formatted `body` |
| `{{#each}}` | Iterating arrays such as the import list |
